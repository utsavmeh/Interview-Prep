> **Module:** Phase 1 — Module 3 (Routing)
> **Topic:** Shallow Routing
> **Target Audience:** Rails developers preparing for Senior/Lead roles

---

## 1. Overview

### What it is

**Shallow routing** flattens nested URLs for member actions (show, edit, update, destroy) while keeping the parent context only for collection actions (index, create, new).

```ruby
# Without shallow — every action includes parent ID
resources :products do
  resources :reviews
end
# GET /products/42/reviews/7        → show
# PATCH /products/42/reviews/7      → update
# DELETE /products/42/reviews/7     → delete

# With shallow — member actions drop the parent
resources :products do
  resources :reviews, shallow: true
end
# GET /products/42/reviews          → index    (still nested)
# POST /products/42/reviews          → create   (still nested)
# GET /reviews/7                     → show     (shallow!)
# PATCH /reviews/7                   → update   (shallow!)
# DELETE /reviews/7                  → delete   (shallow!)
```

### Why it exists

Deeply nested URLs are ugly, hard to share, and unnecessary once you have the child ID:

```
/products/42/reviews/7/edit   ← long, redundant
/reviews/7/edit               ← clean, review ID is globally unique
```

If a review has a unique ID in the database, you don't need the product ID to find it. Shallow routing reflects this reality.

### When to use shallow routing

| Use shallow when... | Example |
|---|---|
| Child has a globally unique ID | Reviews, comments, attachments |
| Member actions don't need parent context | Show, edit, update, destroy |
| URLs are shared/bookmarked | `/reviews/7` is cleaner to share |
| You want shorter API endpoints | Mobile apps, public APIs |

| Keep full nesting when... | Example |
|---|---|
| Child ID is only unique within parent | Line items (item #3 on order #5 vs order #8) |
| Authorization requires parent context | Always verify parent ownership |
| Collection actions need parent | Index and create stay nested |

### Common misconceptions

| Misconception | Reality |
|---|---|
| "Shallow removes all nesting" | Collection routes (index, create, new) stay nested |
| "Shallow changes the controller" | Same controller — only URLs change |
| "You can't find the parent after shallowing" | Review.find(params[:id]) still works — parent is in the DB |
| "Shallow is always better" | Use when child ID is globally unique and parent isn't needed |

## 2. Core Concepts

### Shallow vs Full Nesting Comparison

```ruby
resources :products do
  resources :reviews, shallow: true
end
```

| Action | Full Nested URL | Shallow URL | Helper (shallow) |
|---|---|---|---|
| index | `/products/42/reviews` | `/products/42/reviews` | `product_reviews_path(42)` |
| new | `/products/42/reviews/new` | `/products/42/reviews/new` | `new_product_review_path(42)` |
| create | `/products/42/reviews` | `/products/42/reviews` | `product_reviews_path(42)` |
| show | `/products/42/reviews/7` | `/reviews/7` | `review_path(7)` |
| edit | `/products/42/reviews/7/edit` | `/reviews/7/edit` | `edit_review_path(7)` |
| update | `/products/42/reviews/7` | `/reviews/7` | `review_path(7)` |
| destroy | `/products/42/reviews/7` | `/reviews/7` | `review_path(7)` |

Key insight: **collection actions stay nested, member actions go shallow.**

### Enabling Shallow Routing

**Per resource:**

```ruby
resources :products do
  resources :reviews, shallow: true
end
```

**Globally for all nested resources:**

```ruby
scope shallow: true do
  resources :products do
    resources :reviews
    resources :attachments
  end
end
```

**Shallow with module prefix:**

```ruby
scope shallow: true do
  resources :products do
    resources :reviews, module: :products
  end
end
# Controller: Products::ReviewsController
# Shallow show: /reviews/7 → Products::ReviewsController#show
```

### Params Change in Shallow Actions

```ruby
# Nested index — has product_id
# GET /products/42/reviews
def index
  @product = Product.find(params[:product_id])  # parent param present
  @reviews = @product.reviews
end

# Shallow show — NO product_id
# GET /reviews/7
def show
  @review = Review.find(params[:id])  # only id, no product_id
end
```

This is the biggest controller change — shallow member actions lose `params[:product_id]`.

### Route Helpers Change Too

```ruby
# Nested helpers (collection actions)
product_reviews_path(@product)           # /products/42/reviews
new_product_review_path(@product)        # /products/42/reviews/new

# Shallow helpers (member actions)
review_path(@review)                   # /reviews/7
edit_review_path(@review)              # /reviews/7/edit
```

Rails generates **both sets** of helpers when shallow is enabled.

## 3. Internal Working

When `shallow: true` is set:

1. Rails generates nested routes for **collection actions** (index, new, create)
2. Rails generates **top-level routes** for **member actions** (show, edit, update, destroy)
3. Member routes use the child resource name only (`/reviews/:id`, not `/products/:product_id/reviews/:id`)
4. Both route sets point to the **same controller**
5. Named helpers for member actions drop the parent prefix (`review_path` not `product_review_path`)

```ruby
# Conceptual expansion of shallow: true
resources :products do
  resources :reviews, only: [:index, :new, :create]  # nested
end
resources :reviews, only: [:show, :edit, :update, :destroy]  # shallow top-level
```

## 4. Architecture

```text
Full Nesting:                          Shallow:
─────────────                          ────────
/products/42/reviews          index     /products/42/reviews          index
/products/42/reviews          create    /products/42/reviews          create
/products/42/reviews/new      new       /products/42/reviews/new      new
/products/42/reviews/7        show      /reviews/7                    show
/products/42/reviews/7/edit   edit      /reviews/7/edit               edit
/products/42/reviews/7        update    /reviews/7                    update
/products/42/reviews/7        destroy   /reviews/7                    destroy
```

Shallow keeps parent context where it's needed (creating/listing) and drops it where it's redundant (viewing/editing a specific record).

## 5. Real Production Examples

### Example 1: E-Commerce Product Reviews

```ruby
resources :products, only: [:index, :show] do
  resources :reviews, only: [:index, :create, :show, :destroy], shallow: true
end

# Browse reviews:     GET  /products/42/reviews
# Submit review:      POST /products/42/reviews
# View one review:    GET  /reviews/7
# Delete review:      DELETE /reviews/7
```

### Example 2: Comment System

```ruby
scope shallow: true do
  resources :articles do
    resources :comments, except: [:new, :edit]
  end
  resources :photos do
    resources :comments, except: [:new, :edit]
  end
end

# Comments on articles: POST /articles/1/comments
# Comments on photos:   POST /photos/5/comments
# View any comment:     GET  /comments/99
```

### Example 3: API with Shallow Resources

```ruby
namespace :api do
  namespace :v1 do
    resources :orders do
      resources :line_items, shallow: true, only: [:index, :create, :show, :destroy]
    end
  end
end
```

## 6. Common Mistakes

### Beginner

**1. Using parent param in shallow actions**

```ruby
# BAD — product_id is NOT available in shallow show
def show
  @product = Product.find(params[:product_id])  # nil!
  @review = @product.reviews.find(params[:id])
end

# GOOD — find review directly
def show
  @review = Review.find(params[:id])
end
```

**2. Using nested helpers for member actions**

```ruby
# BAD — this helper still works but generates nested URL
product_review_path(@product, @review)

# GOOD — use shallow helper for member actions
review_path(@review)
```

### Mid-Level

**3. Shallow when child ID isn't globally unique**

```ruby
# Line items might have ID 1 on multiple orders
# Shallow: GET /line_items/1 — which order's line item?
# Keep full nesting for order line items
resources :orders do
  resources :line_items  # NO shallow
end
```

**4. Forgetting to update tests after enabling shallow**

```ruby
# Test must use shallow path
get review_path(@review)          # not product_review_path(@product, @review)
patch review_path(@review), params: { review: { rating: 5 } }
```

### Senior/Lead

**5. Authorization without parent context**

```ruby
# Shallow show — no product_id in params
# Still verify the review belongs to an accessible product
def show
  @review = Review.find(params[:id])
  authorize @review  # use Pundit/CanCanCan on the review itself
end
```

**6. Inconsistent shallow across the app**

Document which resources use shallow and why. Mixed patterns confuse the team.

## 7. Performance Considerations

Shallow routes are **shorter URLs** — no performance difference in recognition. 

Controller impact: shallow actions use `Review.find(id)` instead of `@product.reviews.find(id)` — one query instead of two. This can be **faster**.

---

## 8. Security Considerations

- **IDOR risk increases** if you rely on parent scoping for authorization
- With shallow routes, always authorize the child record directly
- Don't assume parent ownership — verify in the model or policy

```ruby
# With shallow routing, authorize the review itself
class ReviewPolicy
  def show?
    record.product.visible_to?(user)
  end
end
```

## 10. Best Practices

1. **Default to shallow** for resources with globally unique IDs
2. **Keep nesting** for resources scoped to parent (line items, nested attributes)
3. **Update all helpers** when switching to shallow — member actions use shallow helpers
4. **Update tests** to use shallow paths
5. **Authorize the child record** directly in shallow actions
6. **Document the decision** — why shallow or why not

---

## 11. Anti-Patterns

| Anti-Pattern | Better Approach |
|---|---|
| Shallow for scoped IDs (line items) | Full nesting |
| Accessing `params[:product_id]` in shallow show | `Review.find(params[:id])` |
| Mixing shallow and nested helpers randomly | Consistent helper usage per action type |
| Shallow without updating authorization | Policy on child record |

## 12. Interview Questions

### Basic

**Q: What does `shallow: true` do?**

**A:** Keeps collection routes nested under the parent (`/products/42/reviews`) but moves member routes to the top level (`/reviews/7`). Same controller, shorter URLs for show/edit/update/destroy.

### Intermediate

**Q: What changes in the controller when you enable shallow routing?**

**A:** Member actions (show, edit, update, destroy) no longer receive `params[:product_id]`. You find the child record directly by `params[:id]`. Collection actions (index, create, new) still have the parent param.

### Senior

**Q: When would you NOT use shallow routing?**

**A:** When the child ID is only unique within the parent (line items, nested attributes), when authorization depends on verifying parent ownership via URL, or when the parent context is essential for the action (e.g., adding items to a specific order).

## 13. Practical Examples

### Basic Shallow Setup

```ruby
# config/routes.rb
resources :products do
  resources :reviews, shallow: true
end
```

```ruby
# app/controllers/reviews_controller.rb
class ReviewsController < ApplicationController
  def index
    @product = Product.find(params[:product_id])
    @reviews = @product.reviews
  end

  def create
    @product = Product.find(params[:product_id])
    @review = @product.reviews.build(review_params)
    @review.save ? redirect_to(@review) : render(:new)
  end

  def show
    @review = Review.find(params[:id])
  end

  def destroy
    @review = Review.find(params[:id])
    @review.destroy
    redirect_to product_reviews_path(@review.product)
  end
end
```

### View Helpers

```erb
<%# Collection — nested helpers %>
<%= link_to "All Reviews", product_reviews_path(@product) %>
<%= link_to "Add Review", new_product_review_path(@product) %>

<%# Member — shallow helpers %>
<%= link_to @review.title, review_path(@review) %>
<%= link_to "Edit", edit_review_path(@review) %>
<%= button_to "Delete", review_path(@review), method: :delete %>
```

### Global Shallow Scope

```ruby
scope shallow: true do
  resources :articles do
    resources :comments
  end
  resources :photos do
    resources :comments
  end
end
```

## 15. Summary

1. Shallow = **collection stays nested**, **member goes top-level**
2. `/products/42/reviews` (index) vs `/reviews/7` (show)
3. Member actions lose `params[:parent_id]`
4. Use when child ID is **globally unique**
5. Update **helpers and tests** when enabling shallow
6. **Authorize child record** directly in shallow actions
