# Deep Dive into Controller Parameters

## 1. Overview
*   **What it is:** The `params` object in Rails contains all the data sent by the user in an HTTP request. Since Rails 5, it is **not a Hash**, but an instance of `ActionController::Parameters`.
*   **Why it exists:** It unifies data from different sources (the URL query string, form data in the request body, and dynamic segments in the routing path) into a single, accessible object.
*   **When to use it:** Whenever you need to read user input to find a record, create a new object, or filter a list.
*   **Common Misconceptions:**
    *   *"Params is just a Ruby Hash."* (False: Prior to Rails 5, it inherited from `HashWithIndifferentAccess`. Now, it returns an independent `ActionController::Parameters` object to enforce security. Calling hash methods like `.map` on it will fail unless you convert it).
    *   *"Form data and query parameters are handled differently."* (False: Rails merges `GET` query parameters and `POST` body data seamlessly into the same `params` object).

---

## 2. Core Concepts

### Where do `params` come from?
The `params` hash is populated from three main sources:
1.  **Query String:** Information appended to the URL (e.g., `?search=ruby` becomes `params[:search] == "ruby"`).
2.  **Request Body:** Data sent via POST/PUT/PATCH, typically from HTML forms or JSON payloads.
3.  **Routing Parameters:** Dynamic segments defined in `config/routes.rb`. If you have a route like `get '/articles/:id'`, navigating to `/articles/42` sets `params[:id] == "42"`.

### Accessing Parameters
You can access parameters using standard hash notation (symbols or strings are both accepted):
```ruby
def show
  @user = User.find(params[:id])
  @search_query = params[:search]
end
```

### Hash Conversion (to_h vs to_unsafe_h)
Because `params` is no longer a Hash, if you pass it to a method that strictly expects a Ruby Hash (like a 3rd party API client), you must convert it.
*   **`params.to_h`**: Will raise an error if the parameters haven't been explicitly permitted (whitelisted).
*   **`params.to_unsafe_h`**: Bypasses Strong Parameters and converts the raw payload into a Ruby Hash. **Use with extreme caution.**

## 3. Best Practices for Lead Engineers

### 1. Never Trust User Input
The `params` object contains whatever the client decided to send. Never pass the raw `params` hash directly into a database query or a model update. This leads to Mass Assignment vulnerabilities (which we will solve in the next chapter using Strong Parameters).

### 2. Handle Missing Parameters Gracefully
If your code expects a nested hash but the user doesn't send it, `params[:user][:name]` will raise a `NoMethodError` (undefined method `[]` for nil).
Use the `.fetch` method to enforce required parameters or provide defaults:
```ruby
# Raises ActionController::ParameterMissing if :user is absent
user_data = params.require(:user)

# Provides a default if :sort is absent
sort_order = params.fetch(:sort, 'created_at')
```

### 3. Coerce Types Explicitly
Everything in the `params` hash (originating from URL or form-data) is initially a String. Even if a user submits a number `42`, it comes through as `"42"`. Be mindful of type coercion when performing logical checks.
```ruby
# If params[:page] is "1"
params[:page] == 1 # => false
params[:page].to_i == 1 # => true
```

## 4. Interview Preparation

### Q: Why did Rails 5 change `ActionController::Parameters` to no longer inherit from `Hash`?
**A:** Security. Previously, because it was a Hash, developers would accidentally pass the entire `params` object into methods that executed database queries or external API calls, bypassing Strong Parameters entirely. By breaking the inheritance, methods expecting a Hash will now crash, forcing the developer to explicitly call `permit` and then `.to_h`.

### Q: What is the difference between `params[:id]` and `params.require(:id)`?
**A:** `params[:id]` simply returns the value associated with the key `:id` (which might be `nil` if the user didn't send it). `params.require(:id)` explicitly checks if the key exists and its value is not blank. If it is missing, it raises an `ActionController::ParameterMissing` exception, which halts the request and typically returns a 400 Bad Request error.
