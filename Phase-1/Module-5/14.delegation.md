# Mastering Delegation

## 1. Overview
*   **What it is:** A design pattern that allows an object to forward method calls to an associated object. In Rails, this is achieved using the `delegate` macro provided by Active Support.
*   **Why it exists:** To conform to the Law of Demeter (principle of least knowledge), keeping code clean, encapsulated, and preventing "train wrecks" (e.g., `user.profile.address.zipcode`).
*   **When to use it:** When an object needs to expose data or behavior of its components or associations without exposing the entire underlying object architecture.
*   **Common Misconceptions:**
    *   *"Delegation is an alternative to inheritance."* (False: Delegation is about composition—forwarding messages to composed objects—whereas inheritance models an 'is-a' relationship).

---

## 2. Core Concepts

### The delegate macro in ActiveRecord
The `delegate` macro maps a method to a specified target object (usually an association). 

```ruby
class User < ApplicationRecord
  has_one :profile
  # Instead of user.profile.first_name, we can call user.first_name
  delegate :first_name, :last_name, to: :profile
end
```

### The prefix option
Prefixes prevent naming collisions and clarify where the delegated data is coming from.

```ruby
class Invoice < ApplicationRecord
  belongs_to :client
  # Exposes `client_name` and `client_email` instead of just `name` and `email`
  delegate :name, :email, to: :client, prefix: true
  
  # Custom prefix: exposes `customer_name`
  delegate :name, to: :client, prefix: :customer
end
```

### The allow_nil option
By default, if the target of delegation is nil, Rails raises a `Module::DelegationError`. `allow_nil: true` rescues this and returns `nil`.

```ruby
class Post < ApplicationRecord
  belongs_to :author, optional: true
  # If author is nil, post.name returns nil instead of crashing
  delegate :name, to: :author, allow_nil: true
end
```

### Ruby's Forwardable vs Rails delegate
Ruby includes a standard library module called `Forwardable` (`def_delegator`). Rails' `delegate` is similar but adds syntactic sugar specifically for Active Record models, such as `allow_nil` and `prefix`.

## 3. Best Practices for Lead Engineers

### 1. Avoid the Over-Delegation Anti-Pattern
Don't delegate everything just to hide associations. If you are delegating 10 methods to a `Profile` model, the `User` is accumulating too many responsibilities (God Object antipattern). It's often better to interact with the associated object directly if it has a distinctly separate business context.

### 2. Use Delegation for API Design and Presenters
Delegation shines in View Models, Presenters, and API serializers. You can wrap a complex set of models and expose only the safe, necessary attributes to the view or JSON serializer without leaking database structures.

### 3. Delegate vs Wrapper Methods
If you are strictly passing a message through, use `delegate`. If you need to transform the data, add fallback logic, or combine fields, write an explicit wrapper method instead.

```ruby
# Good: Pure delegation
delegate :email, to: :user

# Good: Wrapper method for formatting
def formatted_email
  user ? user.email.downcase : 'no-email@example.com'
end
```

## 4. Interview Preparation

### Q: What is the Law of Demeter and how does delegation help?
**A:** The Law of Demeter says a module should not know about the inner workings of the objects it manipulates ("only talk to your immediate friends"). Delegation helps by preventing long object chains (`user.account.stripe_customer_id`). Instead, `user` delegates `stripe_customer_id` to `account`, so external objects only talk to `user`.

### Q: When is delegation considered an anti-pattern?
**A:** It becomes an anti-pattern when it obscures the domain model or leads to a "God Object." For example, if an `Order` model delegates 20 methods to `Customer`, `Payment`, and `Shipping`, it becomes a dumping ground for logic. It's also an anti-pattern to delegate methods that mutate state on the target object unexpectedly.

### Q: What happens if the target of a delegation is `nil` in Rails?
**A:** By default, it raises a `Module::DelegationError`. To prevent application crashes when the association might be nil, you should use the `allow_nil: true` option, which safely returns `nil` instead.

### Q: How does Rails `delegate` differ from manual wrapper methods?
**A:** Rails `delegate` dynamically generates the forwarding methods at runtime via metaprogramming, providing a declarative syntax that handles caching, prefixing, and nil-checking cleanly. Manual wrappers are explicit definitions (`def name; association.name; end`), which are better when custom transformation is required.
