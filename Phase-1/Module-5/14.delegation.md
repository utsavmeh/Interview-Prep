# Mastering Delegation

## 1. What is delegation?

**Delegation** means asking one object to perform a task on your behalf.

Imagine a `User` has a `Profile`. Without delegation, code may look like this:

```ruby
user.profile.first_name
```

The caller must know that the name is inside `profile`. With delegation:

```ruby
class User < ApplicationRecord
  has_one :profile
  delegate :first_name, :last_name, to: :profile
end
```

The caller can say:

```ruby
user.first_name
```

The `User` forwards the request to its profile. This follows the **Law of Demeter**: an object should talk mostly to its immediate collaborators instead of reaching through several objects.

## 2. Prefixes make delegated methods clear

A prefix is useful when the delegated method name is too general or might collide with another method:

```ruby
class Invoice < ApplicationRecord
  belongs_to :client

  delegate :name, :email, to: :client, prefix: true
end
```

Rails creates methods such as:

```ruby
invoice.client_name
invoice.client_email
```

You can choose your own prefix:

```ruby
delegate :name, to: :client, prefix: :customer
# invoice.customer_name
```

## 3. What if the target is nil?

By default, calling a delegated method when the target is `nil` raises an error:

```ruby
class Post < ApplicationRecord
  belongs_to :author, optional: true
  delegate :name, to: :author
end

post.author # nil
post.name   # raises ActiveSupport::DelegationError
```

If `nil` is a valid situation, allow it explicitly:

```ruby
delegate :name, to: :author, allow_nil: true

post.name # nil
```

Use `allow_nil` only when `nil` is expected. Otherwise, the error can help reveal invalid data.

## 4. Delegation versus a wrapper method

Use delegation when the method is passed through unchanged:

```ruby
delegate :email, to: :user
```

Write a normal method when you need formatting, fallback logic, or other behavior:

```ruby
def display_email
  user&.email&.downcase || "No email provided"
end
```

A wrapper communicates that the `Order` is adding behavior; delegation communicates that it is simply exposing an existing capability.

## 5. When should you use it?

Delegation is useful in models, presenters, view models, and serializers where you want a small, intentional public interface.

Avoid delegating dozens of methods from many objects. For example, if `Order` delegates everything from `Customer`, `Payment`, and `Shipping`, it becomes a confusing “God object.” Keep the interface small and meaningful.

## 6. Delegation versus inheritance

These ideas are different:

```text
Inheritance:  a Car is a Vehicle
Delegation:   a Car asks an Engine to start
```

Inheritance models an **is-a** relationship. Delegation models a **has-a/uses-a** relationship through composition.

## 7. Quick interview answers

**What problem does delegation solve?**  It hides object structure and prevents long chains such as `user.profile.address.city`.

**What happens when the target is nil?**  Rails raises `ActiveSupport::DelegationError` unless `allow_nil: true` is used.

**When should I use a wrapper method?**  When you need to transform, combine, or provide fallback behavior rather than simply forward a call.
