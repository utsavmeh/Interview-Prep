# Mastering Enums

## 1. Overview
*   **What it is:** A Rails feature that maps a predefined set of strings or integers in the database to constant-like values in the model, providing handy scope and predicate methods.
*   **Why it exists:** To make code more readable and self-documenting. Instead of checking if `status == 1`, you check `status.published?`.
*   **When to use it:** For attributes that represent a distinct state, category, or type (e.g., status, roles, access levels, visibility).
*   **Common Misconceptions:**
    *   *"You must use integers in the database for enums."* (False: Rails 7+ fully supports and often encourages string-backed enums to avoid mapping fragilities).

---

## 2. Core Concepts

### Defining Enums (Integer vs String Backed)
By default, arrays map to integers based on index. Hashes let you explicitly define the database value.

```ruby
class Article < ApplicationRecord
  # Integer-backed (Array): DB stores 0, 1, 2. Highly fragile!
  enum status: [ :draft, :published, :archived ]

  # Integer-backed (Hash): Safe against reordering
  enum status: { draft: 0, published: 1, archived: 2 }

  # String-backed (Rails 7+ pattern): DB stores 'draft', 'published'
  enum status: { draft: 'draft', published: 'published', archived: 'archived' }
end
```

### Auto-Generated Methods
When you define an enum, Active Record automatically generates several methods:

```ruby
article.published!     # Bang method: Updates the DB and object to 'published'
article.published?     # Predicate method: Returns true if status is published
Article.published      # Scope: Returns all published articles
Article.not_published  # Negative scope (Rails 6+)
```

### Enum with Prefix and Suffix
To avoid method name collisions (e.g., if you have `enum status: [:active]` and `enum role: [:active]`), use prefixes or suffixes.

```ruby
class User < ApplicationRecord
  enum status: { active: 0, suspended: 1 }, prefix: true
  enum role:   { admin: 0, active: 1 }, suffix: true
end

user.status_active? # rather than just active?
user.admin_role?    # rather than just admin?
```

### Bitwise Enums (Advanced)
Useful for storing multiple flags in a single integer column using powers of two (not native to `enum`, often built manually or via gems, but important conceptual knowledge for leads).

## 3. Best Practices for Lead Engineers

### 1. Beware the Integer Mapping Fragility
Never use the array syntax `enum status: [:draft, :published]` in production. If a developer inserts `in_review` between them, it shifts the integer mappings, silently corrupting all historical database records. Always explicitly define mappings using a Hash.

### 2. Prefer String-Backed Enums
In modern applications, storage space is cheap. Storing strings (like `'published'`) directly in the database makes ad-hoc SQL queries, debugging, and data warehousing massively easier. You don't have to look up what `status: 3` means.

### 3. Be Careful with Bang Methods
The generated bang method (e.g., `article.published!`) skips some validation flows and directly executes an `UPDATE` query immediately modifying the record. If your state transitions require complex logic or side effects, write custom transition methods instead of exposing the raw bang method.

## 4. Interview Preparation

### Q: What is the risk of adding new enum values to an array-based enum?
**A:** Array-based enums map values to their array index. If you insert a new value in the middle or remove an old one, the indices shift. This completely corrupts existing database records. For instance, if `[draft, published]` becomes `[draft, review, published]`, all previously `published` (index 1) records suddenly become `review`.

### Q: How do you safely add new enum values to a live application?
**A:** By using Hash syntax. You define the new key-value pair at the end of the Hash with a new unique integer (or string) mapped to it. E.g., `enum status: { draft: 0, published: 1, archived: 2, review: 3 }`.

### Q: Why might you choose string-backed enums over integer-backed enums?
**A:** String-backed enums improve database readability for data engineers, DBAs, and debugging via SQL. They also prevent the exact mapping corruption issues that integer enums face. The minor tradeoff in database index size is usually negligible compared to the operational benefits.

### Q: How do you resolve naming collisions between two enums on the same model?
**A:** By using the `_prefix: true` or `_suffix: true` options when defining the enum. This appends or prepends the attribute name to the generated predicate, bang, and scope methods, ensuring uniqueness (e.g., `status_active?` vs `role_active?`).
