# Mastering Enums

## 1. What is an enum?

An **enum** represents a value that can only be one of a small, known set of choices.

Imagine an article moving through a workflow:

```text
Draft  ->  Published  ->  Archived
```

Instead of scattering strings throughout the application:

```ruby
article.status == "published"
```

Rails lets us define the choices once and gives us helpful methods:

```ruby
article.published? # true or false
article.published! # changes and saves the status
Article.published  # all published articles
```

Typical enum attributes include `status`, `role`, `visibility`, and `payment_state`.

## 2. Defining an enum

### Integer-backed enum

A hash makes the database mapping explicit:

```ruby
class Article < ApplicationRecord
  enum :status, {
    draft: 0,
    published: 1,
    archived: 2
  }
end
```

The database stores a number, but Ruby presents a readable name:

```text
Ruby:     article.status       => "published"
Database: status column        => 1
```

### String-backed enum

A string-backed enum stores the readable value itself:

```ruby
class Article < ApplicationRecord
  enum :status, {
    draft: "draft",
    published: "published",
    archived: "archived"
  }
end
```

```text
Ruby:     article.status       => "published"
Database: status column        => "published"
```

String-backed enums are often easier to inspect in SQL and safer for reporting. Integer-backed enums use less storage, but the mapping must be managed carefully.

> Rails enum syntax can vary slightly by Rails version. The examples use the modern `enum :status, ...` form.

## 3. Methods Rails creates for you

For the enum above, Rails provides:

```ruby
article.status = :draft
article.draft?       # true
article.published?   # false
article.published!   # updates the record immediately

Article.published     # a scope: all published articles
Article.not_published # all articles that are not published
```

Use `update!` when you want validations and other update behavior to be explicit:

```ruby
article.update!(status: :published)
```

The bang method saves immediately, so do not call it accidentally while only preparing an object in memory.

## 4. Prefixes and suffixes

Two enums can contain the same value name. Prefixes and suffixes prevent confusing method collisions:

```ruby
class User < ApplicationRecord
  enum :status, { active: 0, suspended: 1 }, prefix: true
  enum :role,   { admin: 0, active: 1 }, suffix: true
end
```

Now the generated methods are clear:

```ruby
user.status_active? # checks status
user.active_role?   # checks role
```

## 5. Safe enum changes

Avoid array syntax in production:

```ruby
# Fragile: draft=0, published=1, archived=2
enum :status, [:draft, :published, :archived]
```

If someone inserts a value in the middle, existing meanings change:

```text
Before: 1 means published
After:  1 means in_review  <- old records are now misread
```

Use an explicit hash instead, and assign new integer values without reusing old ones:

```ruby
enum :status, {
  draft: 0,
  published: 1,
  archived: 2,
  in_review: 3
}
```

For a larger workflow, consider a state machine or a separate transition table. An enum is best for a small, stable set of choices.

## 6. Quick interview answers

**What is an enum?**  A mapping between a fixed set of readable model values and database values. Rails adds predicates, bang methods, and scopes.

**Why avoid array-backed enums?**  Array positions are the database mapping. Reordering or removing values can change the meaning of existing records.

**When should I use a string-backed enum?**  When database readability, SQL reporting, and integration with other systems matter more than saving a small amount of storage.

**How do I avoid method collisions?**  Use `prefix: true` or `suffix: true`.
