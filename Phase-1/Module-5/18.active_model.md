# Mastering Active Model

## 1. What is Active Model?

**Active Model** is a collection of Rails modules that give ordinary Ruby objects model-like behavior. It does not connect an object to a database table.

Think of the difference this way:

```text
Active Record = model behavior + database persistence
Active Model  = model behavior without database persistence
```

Use Active Model for form objects, search filters, service inputs, and API request objects.

## 2. A simple form object

```ruby
class ContactForm
  include ActiveModel::Model

  attr_accessor :name, :email, :message

  validates :name, :message, presence: true
  validates :email, format: { with: URI::MailTo::EMAIL_REGEXP }

  def deliver
    return false unless valid?

    ContactMailer.send_message(self).deliver_now
    true
  end
end
```

The object is not saved to a `contact_forms` table, but it can still:

```ruby
form = ContactForm.new(name: "Sam", email: "sam@example.com")
form.valid?
form.errors.full_messages
```

A controller can use the same validation flow as it would for a database-backed model.

## 3. `ActiveModel::Model` and `ActiveModel::API`

`ActiveModel::Model` is a convenient bundle that provides model-like initialization and validation support. `ActiveModel::API` provides the basic model API and attribute initialization; add the modules you actually need.

For a plain object, start simply:

```ruby
class SearchFilter
  include ActiveModel::Model

  attr_accessor :query
  validates :query, presence: true
end
```

The exact modules available can vary by Rails version. Read the API for the version used by your application before replacing one bundle with another.

## 4. Type-cast attributes with `ActiveModel::Attributes`

HTML form values arrive as strings. `ActiveModel::Attributes` can convert them to useful Ruby types:

```ruby
class SearchFilter
  include ActiveModel::Model
  include ActiveModel::Attributes

  attribute :start_date, :date
  attribute :limit, :integer, default: 20
end

filter = SearchFilter.new(start_date: "2023-01-01", limit: "50")
filter.start_date # a Date
filter.limit      # 50 as an Integer
```

Without type casting, a value such as `"50"` may remain a string and produce surprising comparisons.

## 5. Useful Active Model modules

Active Model is modular. Common pieces include:

```text
ActiveModel::Validations  -> validates and errors
ActiveModel::Attributes   -> typed attributes and casting
ActiveModel::Callbacks    -> before/after callbacks
ActiveModel::Naming       -> model names for forms and routes
ActiveModel::Conversion   -> model conversion methods such as to_model
```

`ActiveRecord::Base` uses many of these ideas, but Active Model itself does not create, read, update, or delete database rows.

## 6. When should you use a form object?

Use one when a screen represents an action rather than one table:

```text
Checkout form
  -> validates address
  -> charges payment
  -> creates order
  -> sends confirmation
```

A form object keeps these inputs and validations together instead of putting unrelated rules into `User` or `Order`.

It is also useful for search filters and service objects that need standard Rails errors. Do not add Active Model just because a small plain Ruby class exists; use it when Rails model behavior makes the interface clearer.

## 7. How does `form_with` work with a PORO?

Rails form helpers look for model-like methods such as `model_name`, `to_model`, and naming information. Active Model supplies these conventions, allowing a form object to participate in form building and error display.

The object still needs attributes for the fields:

```ruby
class LoginForm
  include ActiveModel::Model
  attr_accessor :email, :password
end
```

## 8. Quick interview answers

**What is the difference between Active Model and Active Record?**  Active Record includes database persistence and ORM behavior. Active Model provides reusable model behavior without requiring a table.

**When would you use a form object?**  When a form does not map one-to-one to a database record or coordinates several models and external actions.

**What does `ActiveModel::Attributes` provide?**  Typed attributes, defaults, and type casting for plain Ruby objects.

**Can an Active Model object be saved automatically?**  No. It has no database persistence unless you write that behavior yourself or combine it with another object.
